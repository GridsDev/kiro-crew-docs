# ภาคผนวก ก — ตั้งค่า Discord

ทำไมต้องทำเอง: ขั้นตอนนี้ต้องใช้บัญชี Discord ของพี่ฆังและเบราว์เซอร์
ฌอนทำแทนไม่ได้ และ **ไม่ควรทำแทน** เพราะมีโทเคนอยู่ตรงนั้นขั้นเดียว

::: danger กฎเหล็กของหน้านี้
โทเคนไม่เคยผ่านแชท ไม่ผ่านคำสั่งที่พิมพ์ลงเทอร์มินัล และไม่ถูกบันทึกลงไฟล์อื่น
ถ้าวันไหนเห็นโทเคนขึ้นมานอก `~/.kiro/crew/.env` ให้ถือว่ารั่วทันที แล้วไปกดออกโทเคนใหม่ที่ Discord Portal
:::

::: warning Discord ยังไม่ได้เชื่อม
Kiro Crew ติดตั้งแล้ว (`0.7.2`) แต่ **ยังไม่ได้เชื่อม Discord** — `discord.enabled = false`, ไม่มีบอท token, `allowed_user_ids` ว่าง และไฟล์ `.env` ยังไม่ถูกสร้าง
ปฏิบัติตามคู่มือนี้ได้ทันทีเมื่อ `พี่ฆัง` เตรียมบอทตามขั้นที่ ๑–๓ ด้านล่าง
ผลกระทบต่อระบบเดิมที่ยังไม่ทดสอบ: Message Content Intent, DM vs shared guild, OAuth scopes — ดู [๙. ปรับปรุงแก้ไข](/improvements)
:::

---

## ขั้นที่ ๑ — สร้างแอปและบอท

ที่ `https://discord.com/developers/applications` — ทำในเบราว์เซอร์

| สิ่งที่ต้องทำ | หมายเหตุ |
|---|---|
| กด **New Application** | ตั้งชื่อที่จำได้ เช่น `Kiro Crew` |
| เปิดแอปที่สร้าง | หน้า Overview ของแอป |
| ไปหน้า **Bot** | อยู่ในเมนูด้านซ้าย |
| กด **Reset Token** | โทเคนจะแสดง **ครั้งเดียวเท่านั้น** |

::: danger ตอนกด Reset Token
หน้าต่างจะขึ้นมาครั้งเดียว ถ้าปิดไปแล้วต้องกด Reset ใหม่
อย่าคัดลอกโทเคนนี้ไปส่งในแชท อย่าวางในไฟล์อื่น อย่าอยู่ในประวัติคำสั่ง
เก็บไว้เพื่อขั้นที่ ๓ เท่านั้น
:::

## ขั้นที่ ๒ — เปิด Intent ที่จำเป็น

อยู่หน้า **Bot** หัวข้อ **Privileged Gateway Intents**

| Intent | ต้องเปิด | เพราะ |
|---|---|---|
| **Message Content Intent** | ✅ จำเป็น | ถ้าไม่เปิด บอทจะอ่านข้อความไม่ได้เลย |
| Server Members Intent | ไม่ต้อง | ระบบนี้ใช้ DM เป็นหลัก ไม่ต้องรู้สมาชิกในเซิร์ฟเวอร์ |

::: tip เปิด Message Content แล้วเสี่ยงอะไร
Intent นี้ทำให้บอท "เห็น" ข้อความทุกช่องที่มันอ่านได้
เพราะระบบนี้ไม่ได้ถูกเชิญเข้าเซิร์ฟเวอร์ใด ๆ และใช้ allowlist บังคับอีกชั้น ความเสี่ยงจึงต่ำ
แต่ถ้าภายหลังเชิญบอทเข้าเซิร์ฟเวอร์ใหญ่ ต้องกลับมาคิดเรื่องนี้ใหม่ — ดู [๖. ความปลอดภัย](/security)
:::

## ขั้นที่ ๓ — เก็บโทเคนบน `sv`

เชื่อมต่อ `sv` แล้วเปิดไฟล์ env ด้วยโปรแกรมแก้ข้อความ

```bash
# เปิดไฟล์เพื่อแก้ไข (พิมพ์เอง ไม่ต้องส่งให้ใครเห็น)
nano ~/.kiro/crew/.env
```

เพิ่มบรรทัดนี้

```
DISCORD_BOT_TOKEN=<วางโทเคนที่ได้จากขั้นที่ ๑>
```

เสร็จแล้วปิดไฟล์ แล้วตรวจว่าสิทธิ์ไฟล์เป็นของพี่ฆังคนเดียว

```bash
chmod 600 ~/.kiro/crew/.env
```

::: warning อย่าตรวจไฟล์นี้ด้วยคำสั่งที่พิมพ์ค่าออกมา
คำสั่งอย่าง `cat ~/.kiro/crew/.env` จะพิมพ์โทเคนออกมาบนหน้าจอและเข้า log
ถ้าจะตรวจว่ามีตัวแปรอยู่จริง ให้ถาม `kirocrew doctor` แทนซึ่งจะบอกสถานะโดยไม่เผยค่า
:::

## ขั้นที่ ๔ — ใส่ User ID ใน allowlist

ระบบนี้เป็น **ปิดเป็นค่าเริ่มต้น** — แม้แต่เจ้าของบอทเอง ถ้าไม่อยู่ในรายการก็ส่ง DM ไม่ได้

หา User ID ของพี่ฆังก่อน

| สิ่งที่ต้องทำ | รายละเอียด |
|---|---|
| Discord → **User Settings** | หัวข้อ **Advanced** |
| เปิด **Developer Mode** | สวิตช์สีหวานไปเปิด |
| คลิกขวาชื่อผู้ใช้ | เลือก **Copy User ID** — ได้ตัวเลขยาว ๆ เช่น `123456789012345678` |

แก้ไฟล์ `~/.kiro/crew/config.json`

```json
{
  "discord": {
    "enabled": true,
    "allowed_user_ids": ["<วาง User ID ของพี่ฆัง>"]
  }
}
```

::: warning ชื่อคีย์ต้องตรงตามนี้
คีย์ที่ระบบอ่านจริงคือ `allowed_user_ids` **ไม่ใช่** `allowed_users`
(`allowed_users` เป็นคีย์ของ Slack — คนละช่องกัน)
ตรวจได้ด้วย `kirocrew config get discord` ว่าค่าที่ใส่ถูกเข้าไปจริง
:::

::: info ทุกครั้งที่เพิ่มผู้ใช้ ระบบจะบันทึก audit ไว้เอง
นี่เป็นค่าเริ่มต้นของระบบ ไม่ต้องทำอะไรเพิ่ม
ใส่แค่คนเดียวก่อน ให้ทำงานได้จริงค่อยเพิ่มคนที่สอง — ดู [๖. ความปลอดภัย](/security)
:::

## ขั้นที่ ๕ — เชิญบอทเข้า (ถ้าจำเป็น)

ระบบนี้ใช้ **DM เป็นหลัก** จึงไม่ต้องเชิญเข้าเซิร์ฟเวอร์ใด ๆ

| กรณี | ต้องเชิญไหม |
|---|---|
| ใช้งานผ่าน DM อย่างเดียว | ❌ ไม่ต้อง |
| ต้องการคุยในเซิร์ฟเวอร์ของตัวเอง | ✅ ต้อง — ใช้ OAuth2 URL Generator |

ถ้าต้องเชิญ ให้ตั้งค่าในหน้า **OAuth2 → URL Generator** แบบขั้นต่ำที่สุด

| ช่อง | ค่า |
|---|---|
| Scopes | `bot` (เพิ่ม `applications.commands` ถ้าอยากใช้ slash command) |
| Bot Permissions | ไม่ให้สิทธิ์ในเซิร์ฟเวอร์ — DM ไม่ต้องใช้ |

::: danger ห้ามให้สิทธิ์ Administrator
ไม่ว่าจะดูจำเป็นแค่ไหนก็ตาม ไม่ใช้ Administrator
ระบบนี้ทำงานได้ครบโดยไม่ต้องใช้สิทธิ์ระดับนั้น และสิทธิ์เกินจำเป็นคือความเสี่ยงที่ไม่มีเหตุผล
ถ้าบอทต้องทำอะไรที่ต้องใช้สิทธิ์ ให้กลับมาคุยก่อน ไม่ใช่เปิดสิทธิ์ให้กว้างแล้วค่อยดูว่าจะพังไหม
:::

## ขั้นที่ ๖ — ตรวจว่าใช้ได้

```bash
# ตรวจสถานะรวม — บอกได้ว่า Discord เชื่อมแล้วหรือยัง
kirocrew doctor

# ถ้ายังไม่ติดอะไร เริ่มหรือหยุดใหม่
kirocrew restart
```

ผลที่ต้องเห็น

| ต้องเห็น | ถ้าไม่เห็น |
|---|---|
| Discord เชื่อมต่อแล้ว | ตรวจว่าไฟล์ `.env` อยู่ที่ถูกที่ และสิทธิ์เป็น 600 |
| ไม่มีข้อผิดพลาดเรื่องโทเคน | ถ้าโทเคนผิดจะขึ้นว่า authentication failed |
| ไม่มีเลข 429 ซ้ำ ๆ | 429 คือถูก Discord จำกัดอัตรา — ลดความถี่ในการส่ง |

::: tip ส่งข้อความแรก
เปิด Discord → DM ไปที่บอทที่เพิ่งเพิ่ม
พิมพ์คำถามง่าย ๆ หนึ่งประโยค แล้วดูว่ามีคำตอบตอบกลับมาไหม

ถ้าบอทไม่ตอบเลย ให้เช็คตามลำดับนี้: อยู่ใน `allowed_user_ids` ไหม → `discord.enabled` เป็น `true` ไหม → โทเคนถูกไหม → มี `Message Content Intent` ไหม → อยู่ในช่อง/เธรดที่อนุญาตไหม
:::

## หลังติดตั้งแล้วจะใช้อะไรได้

| ความสามารถ | รายละเอียด |
|---|---|
| คุย DM | ทุกข้อความจากคนเดิมอยู่ session เดียวกัน ต่อเนื่อง |
| หมดอายุ session | ไม่มีข้อความเกิน **๖๐ นาที** โดยปริยาย (`session.timeout_secs = 3600`) — ปรับได้ |
| อนุมัติคำสั่ง | ปุ่ม **Approve** / **Reject** ในตัวข้อความ หมดเวลา **๒ ชั่วโมง** แล้วปฏิเสธให้อัตโนมัติ |
| หยุดงานที่ค้าง | ส่ง `!stop` — ยกเลิกทั้งรอบที่กำลังทำและคำขออนุมัติที่ค้างอยู่ |
| ส่งไฟล์ | รูปภาพส่งตรงเข้าช่องสายตา · ไฟล์ข้อความถูกฝังในข้อความ · ไฟล์เสียงถูกถอดเสียงได้ |
| ข้อความยาว | Discord ตัดที่ ๒๐๐๐ ตัวอักษรต่อข้อความ ระบบแบ่งให้เอง |
| ปุ่มอนุมัติ | ได้สูงสุด ๓ ปุ่มต่อการ์ด |

::: info ไฟล์จากคนที่ไม่อยู่ใน allowlist จะถูกทิ้งเงียบ ๆ
ไม่มีการแจ้งเตือน ไม่มี error — เป็นพฤติกรรมที่ตั้งใจทำ ไม่ใช่ของเสีย
:::

::: warning ข้อจำกัดที่ต้องรู้ก่อนใช้งานจริง
งานที่ต้องรันอัตโนมัติโดยไม่มีคนกดอนุมัติ **จะใช้เครื่องมือไม่ได้** เมื่ออยู่โหมด interactive
เพราะไม่มีคนมากดอนุมัติ ระบบจะปฏิเสธเอง (ปิดเป็นค่าเริ่มต้น)

ทางเลือกคือ ใช้ Discord สำหรับคุยและสั่งงานที่ต้องการการกำกับดู
ส่วนงานเครื่องมือหนัก ๆ ให้ทำผ่าน dashboard แทน
:::

## ถ้ามีปัญหา

| อาการ | ตรวจตรงนี้ |
|---|---|
| บอทไม่ตอบ | `kirocrew doctor` — ดูว่าเชื่อมต่อแล้วหรือยัง |
| คนอื่น DM ไม่ได้ ทั้งที่พี่ฆังได้ | เพิ่ม User ID นั้นใน `discord.allowed_user_ids` |
| ปุ่มอนุมัติกดแล้วไม่มีอะไรเกิด | บอทต้องออนไลน์อยู่ — ดู log ว่า websocket หลุดไหม |
| ข้อความยาวถูกตัด | ตามธรรมชาติระบบแบ่งให้แล้ว ถ้ายังถูกตัดแปลว่ามีตัวจัดรูปแบบข้อความที่เขียนเอง |
| ไฟล์เสียงไม่ถูกถอด | ต้องตั้ง `voice.stt_provider` — ไม่ได้ทำเป็นค่าเริ่มต้น |
| เห็น 429 ซ้ำ ๆ | ถูกจำกัดอัตราต่อช่องทาง REST ของ Discord — ระบบถอยเอง แต่ลดความถี่ในการส่งเถอะ |

## ค่าตั้ง Discord ที่ต้ารู้จัก

ทั้งหมดอยู่ใต้ `discord.*` ใน `~/.kiro/crew/config.json` — รายการนี้ยืนยันจาก `kirocrew config get discord` บน `sv` แล้ว

| คีย์ | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `discord.enabled` | `false` | สวิตช์หลัก |
| `discord.bot_token` | `""` | โทเคนบอท — อย่าใส่ในไฟล์ที่แชร์ได้ |
| `discord.allowed_user_ids` | `[]` | รายการ User ID ที่อนุญาต — ปิดเป็นค่าเริ่มต้น |
| `discord.allowed_channel_ids` | `[]` | จำกัดเฉพาะช่องที่อนุญาต (ถ้าใช้งานผ่านช่อง) |
| `discord.allowed_thread_ids` | `[]` | จำกัดเฉพาะเธรดที่อนุญาต |
| `discord.auto_thread` | `true` | สร้างเธรดต่อหนึ่งเรื่องโดยอัตโนมัติ |
| `discord.show_thinking` | `false` | แสดงสถานะกำลังคิด |

::: info ไม่มีคีย์ `enterprise_id` หรือ `command_prefix` สำหรับ Discord
ถ้าเอกสารใดบอกว่ามี แปลว่าผิด — ยืนยันจาก `kirocrew config get discord` เสมอ
:::

|---|---|
