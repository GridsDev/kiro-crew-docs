# ๙. ส่งงาน

หน้านี้สรุปสิ่งที่ส่งมอบ สิ่งที่ยังไม่ได้ทำ และวิธีทำงานต่อ

::: danger ขอพูดตรง ๆ ก่อน
งานรอบนี้**ติดตั้ง Kiro Crew บน `sv` แล้ว** แต่ยัง**ใช้งานจริงไม่ได้**
ยังไม่มี service · ยังไม่มีนโยบาย/profile · sandbox ใช้ไม่ได้ · Discord ปิด · ยังไม่เปิดทางเข้า

R1–R16 ยังไม่ผ่านสักข้อ โดยรายละเอียดอยู่ที่ [๕. การตรวจสอบ](/verification)
:::

## สิ่งที่ยังไม่ได้ทำ

รายการนี้ **ตั้งใจไม่ให้พลาด** เพราะแยก “ติดตั้งแล้ว” ออกจาก “ใช้งานได้แล้ว” ให้ชัด

| ยังไม่ทำ | เหตุผล |
|---|---|
| ✅ ติดตั้ง systemd service | `kirocrew service install` ผ่าน `~/python-tools/sv.py` · ได้ system-level ที่ `/etc/systemd/system/kirocrew.service` · ไม่ต้องเปิด linger |
| ✅ ติดตั้ง AppArmor profile ให้ sandbox ใช้ได้ | ทำได้ในคำสั่งเดียวกันคือ `kirocrew service install` (sudo) · ต้องลดสิทธิ์ `/home/devg/.kiro` เป็น `750` ก่อน |
| สร้าง `config.json` (ยังไม่เคยมีไฟล์นี้) | ค่าที่อ่านได้ทั้งหมดตอนนี้คือค่าเริ่มต้น ยังไม่ได้ตั้งอะไร |
| สร้าง `security_policy.json` และ `profiles/` | ยังไม่ได้ออกแบบให้เหมาะกับงานแต่ละแบบ |
| ตั้ง `agent.approval_mode = interactive` | ปัจจุบันยังเป็นค่าเริ่มต้น `auto` |
| หาตำแหน่งจริงของ helper ชื่อ `kiro` | `gateway.log` เรียก `kiro` แต่ `which kiro` ไม่พบ — ต้องรู้ก่อนชี้ `--path` ให้ profile |
| สร้างบอท Discord และใส่โทเคน | พี่ฆังต้องทำเองในเบราว์เซอร์ · `.env` ยังไม่มี |
| เปิด tailnet (`kirocrew tailnet up`) | ยังไม่อนุมัติ · ต้องตรวจผลกระทบ Billing `:8443` ก่อน |
| ทดสอบ R1–R16 จริง | ยังไม่มี service และ sandbox ยังใช้ไม่ได้ |
| เชื่อม `agy` / Copilot / LINE | ยังไม่มีช่องทางที่คุมได้ ดู [๘. ปรับปรุง](/improvements) |

::: warning ถ้าเห็นคำว่า "ติดตั้งแล้ว" ที่ไหน ให้สงสัยก่อน
เอกสารชุดนี้เขียนแยกชัดเจนระหว่างสามสถานะ: **ตรวจแล้วว่ามี** · **ยังไม่ได้ทดสอบ** · **ยังไม่ได้ทำ**
ถ้าเจอข้อความที่ขัดกับหลักนี้ แปลว่าเอกสารเพี้ยน ให้แก้เอกสาร ไม่ใช่แก้ความจริง
:::

## สิ่งที่พี่ฆังต้องทำเอง

รายการนี้ทำแทนไม่ได้ เพราะต้องใช้บัญชี Discord ของพี่ฆัง

| # | เรื่อง | ทำที่ไหน | ดูวิธีที่ |
|---|---|---|---|
| ๑ | สร้างบอทและรับโทเคน | เบราว์เซอร์ — Discord Developer Portal | [ตั้งค่า Discord](/discord-setup) |
| ๒ | รับ User ID ของพี่ฆัง | เบราว์เซอร์ — เปิด Developer Mode | [ตั้งค่า Discord](/discord-setup) |
| ๓ | ใส่โทเคนใน `~/.kiro/crew/.env` | `sv` — พิมพ์เอง ไม่ต้องส่งให้ใครเห็น | [ตั้งค่า Discord](/discord-setup) |
| ๔ | ใส่ User ID ใน allowlist | `sv` — แก้ `~/.kiro/crew/config.json` | [ตั้งค่า Discord](/discord-setup) |
| ๕ | อนุมัติรายการคำสั่งต้องห้าง | `sv` — ตรวจก่อนเชื่อม Discord | [๖. ความปลอดภัย](/security) |

::: danger ข้อ ๓ สำคัญที่สุด
โทเคนไม่เคยถูกส่งผ่านแชท คัดลอก หรือบันทึกลงไฟล์ใด ๆ นอกจาก `~/.kiro/crew/.env`
ถ้าวันหนึ่งเห็นโทเคนในที่อื่น ให้ถือว่ารั่วและไปกดออกโทเคนใหม่ทันทีที่ Discord Portal
:::

## ทำงานต่ออย่างไร

### ขั้นตอนถัดไป — ติดตั้งแล้ว รออนุมัติสิทธิ์ระดับระบบ

Kiro Crew ติดตั้งแล้ว แต่ยังไม่ทำงาน สิ่งที่ต้องทำต่อคือระยะที่ ๒ และระยะที่ ๓ ใน [๔. แผนการทำงาน](/work-plan)
ระยะที่ ๒ (service + AppArmor) ต้องใช้สิทธิ์ sudo — **รอพี่ฆังอนุมัติก่อน ห้ามทำเอง**
แต่ละระยะต้องผ่านเกณฑ์ของตัวเองก่อนขึ้นระยะถัดไป

::: tip จุดหยุดบังคับระหว่างทาง
- ระยะที่ ๒ — ต้องได้รับอนุมัติรายการคำสั่งต้องห้าก่อนเชื่อม Discord
- ระยะที่ ๕ — ต้องทดสอบ R1–R6 ผ่านก่อนเชื่อมผู้ใช้คนที่สอง
- ระยะที่ ๘ — ต้องผ่าน R1–R9 ครบก่อนประกาศว่าเสร็จ
:::

### ขณะรออนุมัติ

เอกสารชุดนี้ใช้อ่านอย่างเดียวก็ได้ มันคือข้อตกลงที่ตกลงกันไว้
ทุกคนที่เกี่ยวข้องจะอ้างอิงหน้าเดียวกัน ไม่ต้องถามซ้ำว่าขอบเขตคืออะไร
ส่วนสถานะที่ทำไปแล้วและสิ่งที่ยังค้างอยู่ดูได้ที่ [๕. การตรวจสอบ](/verification)

### ถ้าอยากแก้เอกสาร

แก้ไฟล์ `.md` ใน `docs/` แล้วรัน `pnpm run build` เพื่อตรวจว่าลิงก์และโครงสร้างไม่พัง

## ปิดท้าย

เอกสารชุดนี้เขียนขึ้นเพื่อให้พี่ฆังอ่านตรวจก่อนเริ่ม และปรับให้ตรงกับสถานะจริงของ `sv` ระหว่างลงมือ
ตอนนี้ติดตั้งเสร็จแล้วแต่ยังไม่ทำงาน — สิ่งที่ขาดคือ service, AppArmor profile, security policy, approval `interactive`, tailnet และ Discord ตามที่ระบุไว้ด้านบน

ทุกข้อมูลในที่นี้มาจากการตรวจระบบจริงบน `sv` ส่วนที่ยังพิสูจน์ไม่ได้ถูกเขียนว่า "ยังไม่ได้ทดสอบ" ไม่ใช่เขียนให้ดูเป็นอย่างอื่น

ถ้าพบว่าข้อมูลส่วนไหนไม่ตรงกับความจริง ให้แก้เอกสารนี้ก่อน แล้วค่อยแก้ระบบ
