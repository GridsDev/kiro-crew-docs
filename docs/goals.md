# ๓. เป้าหมายและผลสำเร็จ

หัวข้อนี้ตอบสองข้อ: **ต้องการให้เป็นแบบไหน** และ **ตอนนี้ไปถึงไหนแล้ว**

## เป้าหมาย

### เป้าหมายหลัก — ระบบผู้ช่วย AI หลายตัวที่ทำงานต่อเนื่อง

สั่งงานจาก Notebook ผ่าน Discord ให้ AI หลายตัวทำงานบน `sv` ได้ โดยพี่ฆังควบคุมได้ทุกขั้น

### เป้าหมายรอง

| # | เป้าหมาย | ทำไมต้องมี |
|---|---|---|
| 1 | **ความต่อเนื่อง** | งานทำต่อได้โดยไม่ต้องเปิดเครื่องคอมพิวเตอร์ |
| 2 | **ความปลอดภัยเป็นค่าเริ่มต้น** | AI ทำงานกับไฟล์จริง ต้องคุมได้ |
| 3 | **ตรวจสอบย้อนหลังได้** | ต้องรู้ว่าทำอะไรไปบ้าง |
| 4 | **เข้าถึงแบบ private** | ไม่เปิดบริการให้ภายนอก |
| 5 | **AI หลายตัวประสานงานกัน** | งานจริงมักเกินขอบเขต AI ตัวเดียว |

## ผลสำเร็จ

::: tip นิยาม
**ผลสำเร็จ = พิสูจน์ได้ด้วยการทดสอบจริง** ไม่ใช่ "ติดตั้งเสร็จแล้ว" — ต้องผ่านเกณฑ์ด้านล่างทุกข้อ
:::

### ระดับที่ ๑ — ต้องผ่าน (ขาดไม่ได้)

| # | เกณฑ์ | วิธีตรวจ |
|---|---|---|
| R1 | สั่งงานจาก Discord DM แล้ว AI ตอบกลับ | ส่งข้อความจริงจากเครื่องพี่ฆัง |
| R2 | **คนอื่นใช้ไม่ได้** | ทดสอบจากเครื่อง/บัญชีที่ไม่อยู่ใน allowlist |
| R3 | **ไม่มี public URL** | ตรวจจากเครือข่ายนอก Tailscale ต้องเข้าไม่ได้ |
| R4 | Dashboard ปฏิเสธเมื่อไม่มีโทเคน | เปิด URL ตรง ๆ โดยไม่ใส่โทเคน |
| R5 | AI ทำงานนอกโฟลเดอร์งานถูกปฏิเสธ | สั่งให้แตะโฟลเดอร์อื่น ต้องถูกบล็อก |
| R6 | คำสั่งต้องห้ามยังถูกบล็อก | ทดสอบคำสั่งต้องห้าม แม้เปิด Autopilot |
| R7 | `!stop` หยุดงานได้จริง | สั่งงานยาวแล้วสั่งหยุด ต้องหยุดทันที |
| R8 | ระบบเปิดขึ้นหลัง reboot | restart เครื่องแล้วต้องกลับมาทำงานเอง |
| R9 | **route เดิมยังใช้ได้** | `:8443` ต้องไม่เสีย |

## เกณฑ์ความปลอดภัยที่ยอมรับไม่ได้

ข้อเหล่านี้ถือว่า **ล้มเหลวทันที** ไม่ต้องดูเกณฑ์อื่น

- ❌ เปิดบริการให้เข้าถึงจากอินเทอร์เน็ตสาธารณะ
- ❌ คนที่ไม่ได้อยู่ใน allowlist สั่งงานได้
- ❌ งานบางอย่างทำได้โดยไม่ผ่านจุดอนุมัติเมื่อควรผ่าน
- ❌ คำสั่งต้องห้ามถูกข้าม
- ❌ อ่านหรือเขียนไฟล์นอกขอบเขตที่กำหนด
- ❌ โทเคนหรือรหัสผ่านถูกเขียนในโค้ด ในเอกสารนี้ หรือในบันทึกคำสั่ง
- ❌ route เดิม `:8443` เสีย

## สถานะปัจจุบัน

::: info สถานะ ณ วันที่ 3 ตุลาคม 2569
**ติดตั้งแล้ว ยังใช้งานจริงไม่ได้** — Kiro Crew 0.7.2 อยู่บน `sv` แล้ว แต่ยังไม่มี service, sandbox ใช้ไม่ได้, Discord ปิด และยังไม่เปิดทางเข้า

### เสร็จแล้ว
- สำรวจความสามารถของเครื่องมือทุกตัวที่จะใช้
- ตรวจสภาพ `sv` — ทรัพยากร พอร์ต เครือข่าย ระบบ
- อ่านเอกสารทางการของ Kiro Crew ครบช่องทางที่เกี่ยวข้อง
- ตัดสินใจเลือก Discord และ Kiro CLI + OpenCode
- เขียนเอกสารชุดนี้

### ยังไม่ทำ
- ติดตั้ง Kiro Crew บน `sv`
- ตั้งค่าความปลอดภัยและ governance
- เชื่อม Discord
- ทดสอบเกณฑ์ระดับที่ ๑ ทั้ง ๙ ข้อ

### สิ่งที่ต้องรอจากพี่ฆัง
- อนุมัติให้เริ่มติดตั้ง
- สร้างบอท Discord และใส่โทเคนกับ User ID

:::

## ข้อจำกัดที่ต้องบอกตามตรง

### ทำได้ — ขึ้นอยู่กับตัว AI ที่เลือกใช้

- ความสามารถในการเขียนโค้ดและวิเคราะห์ของ AI
- จำนวนงานที่ทำได้ในหนึ่งวัน (ขึ้นกับโควตาและเวลาประมวลผล)

### ทำไมได้

- ใช้ทรัพยากร `sv` ที่ตรวจแล้วว่าพอ — RAM ว่าง 25 GiB, ดิสก์ว่าง 51 GB
- Kiro CLI และ OpenCode ติดตั้งและพร้อมใช้งานอยู่แล้ว
- Kiro Crew รองรับสองตัวนี้เป็น backend ในตัว

### ทำไมอาจไม่ได้

- **สิทธิ์ Tailscale ในการแก้ route** — ยังไม่ได้ทดสอบว่าผู้ใช้ `devg` แก้ route ได้ไหม
- **รหัสผ่าน sudo** — ต้องใช้ตอนเปิด service ที่ทำงานหลัง reboot ยังไม่ได้ทดสอบ
- **ความเข้ากันของ Kiro CLI** — เครื่องมีรุ่นที่อาจต่างจากเอกสาร ต้องทดสอบจริง
- **โควตาเครดิต** — ถ้ามีจำกัดจะจำกัดปริมาณงาน เอกสารนี้ยังไม่ยืนยันตัวเลข
